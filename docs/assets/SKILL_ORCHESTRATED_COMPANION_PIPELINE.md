## Purpose

This document defines the reusable Nexus Link companion animation asset production line. It governs how Codex prepares, routes, validates, and reviews companion sprite generation without allowing raw generated output to bypass identity, layout, validation, and human approval gates.

Codex is the pipeline orchestrator. It assembles the lock spec, action config, prompt, reference manifest, generation job, validation command, and review artifacts. It does not promote generated artwork to runtime by default.

## Scope

This pipeline applies to new Nexus Link illustrated companion assets, including ThunderPup and future companions. It does not change runtime code, connect any character to gameplay, or make concept art a runtime asset.

Concept sheets, old atlas images, card art, pixel-style drafts, 64 PPU notes, 96px markings, and approved identity references are canon/reference material only. They are not runtime companion sprite sheets unless a new clean production export is created and approved.

## Pipeline Stages

1. Human selects approved character references.
   - Human provides the highest-priority identity images and marks any supplemental references.
   - Mixed character versions, unrelated evolution stages, UI-heavy card art, and alternate color variants must not be used as primary seeds unless human explicitly pivots canon.

2. Codex creates or updates Character Lock Spec.
   - The lock spec is the identity law for prompt generation and animation consistency.
   - It defines canonical identity, silhouette, face, palette, signature markings, special anatomy, personality read, action-facing rules, and forbidden drift.

3. Codex creates Action Config from Companion Animation Catalog.
   - Action timing, frame count, row/column layout, loop behavior, baseline needs, and allowed motion come from the action config.
   - Action config must not override the character lock spec.

4. Codex builds Generation Job.
   - The job binds character id, action id, backend availability, required skills, source paths, output targets, frame spec, art policy, and approval gates.
   - The job is the handoff contract between Codex orchestration, generation, sprite processing, validation, and human review.

5. Game Studio routes the task as Nexus Link companion asset production.
   - Game Studio is the game asset task router, not the renderer.
   - It confirms this is a Nexus Link companion asset workflow and keeps the task out of unrelated Phaser/runtime implementation paths.

6. Generate 2D Sprite produces raw image or sprite sheet.
   - Generate 2D Sprite is the raw image generation step.
   - It uses the lock spec, reference manifest, action config, prompt, and generation job.
   - Image backend use is allowed only when directly callable and authorized for the task.
   - If image generation is unavailable, Codex outputs the generation package and stops.

7. Sprite Pipeline performs normalization and QC.
   - Sprite Pipeline is the animation sheet consistency and QC step.
   - It may perform sheet normalization, frame layout checks, baseline checks, preview generation, scale consistency checks, and QC reporting.
   - Bottom-center anchoring and baseline stability are required throughout the sheet.

8. Codex runs `validate_companion_asset.js`.
   - Validation must use the expected frame layout from the generation job and action config.
   - Example command shape:

```powershell
node scripts/validate_companion_asset.js --file <processed-sheet.png> --character-id <character-id> --cols <cols> --rows <rows> --expected-frames <frame-count>
```

9. Human performs identity review.
   - Human remains the final art director and identity approval gate.
   - Human reviews likeness, silhouette, palette, markings, special anatomy, action readability, frame consistency, baseline stability, transparent background, and absence of UI/text/scene content.

10. Only approved sheets may be promoted to runtime assets.
   - Runtime promotion requires validator pass and human approval.
   - Raw generated images are never runtime assets.
   - Approved runtime sheet paths must remain explicit in the generation job and human review report.

## Role Boundaries

| Role | Responsibility |
| --- | --- |
| Codex | Pipeline orchestrator. Prepares specs, prompts, manifests, jobs, validation commands, QC reports, and review packages. |
| Game Studio | Game asset task router. Classifies the task as Nexus Link companion production and keeps it in the correct workflow. |
| Generate 2D Sprite | Raw image generation step. Produces the first image or sheet from approved inputs when an image backend is callable. |
| Sprite Pipeline | Sprite sheet normalization and QC step. Checks layout, baseline, anchor, preview, and sheet consistency. |
| Image 2 / image backend | Image generation backend only if callable and authorized. Built-in `image_gen` is available here; model-specific Image 2 controls are unverified. |
| Human | Final art director. Approves references, lock spec changes, generated identity, and any runtime promotion. |

## Hard Rules

- Codex must not generate images unless the task explicitly authorizes image generation.
- Concept sheets are reference/canon only, not runtime assets.
- Raw generated images are never runtime assets.
- Runtime promotion requires validator pass and human approval.
- Character identity must come from the lock spec and reference manifest.
- Action timing and frame layout must come from the action config.
- New illustrated companion assets use 512x512 master frames.
- Final runtime PNG assets must use transparent backgrounds.
- Companion anchor is bottom-center and must remain stable across frames.
- Runtime policy for new illustrated companions is linear sampling plus mipmaps.
- New illustrated companion assets must not use a nearest-neighbor policy.
- Sprite sheet edge length must stay at or below 4096 px.
- Frame grid must divide evenly: sheet width / cols and sheet height / rows must both be integers.
- Scale calculations use frame height, not full sheet height.
- Raw output must not contain baked-in white background, UI, text, scene, pedestal, card frame, or catalog frame.

## Fallback When Image Generation Is Unavailable

If Codex cannot directly invoke Image 2 or another image backend, Codex must output:

- Generation job JSON.
- Prompt text.
- Reference manifest.
- Expected output paths.
- Validation command.

Codex then waits for the human or an external image generation tool to provide the generated PNG. After the PNG is available, Codex can resume at Sprite Pipeline normalization/QC and validator execution.

## ThunderPup Application

For ThunderPup, the generation package uses:

- Character lock spec: `assets/characters/thunder-pup/canon/thunder-pup.lock.md`
- Action config: `assets/characters/thunder-pup/actions/idle_calm.json`
- Prompt artifact: `assets/characters/thunder-pup/prompts/thunder-pup_idle_calm.prompt.txt`
- Human-facing generation checklist: `assets/characters/thunder-pup/qc/thunder-pup_idle_calm_generation_checklist.md`

The lock spec controls the wolf pup identity, electric blue eyes, dark fur palette, blue-violet lightning markings, crystal electric tail tip, and forbidden drift rules. The action config controls the `idle_calm` sheet layout and timing.

## Future Character Application

For each future companion:

1. Create or update a character lock spec.
2. Create or select an action config from the animation catalog.
3. Create a reference manifest with explicit priority rules.
4. Build a generation job from `templates/companion-generation-job.template.json`.
5. Build a skill invocation plan from `templates/skill-invocation-plan.template.md`.
6. Generate only when authorized and backend capability is available.
7. Validate, QC, and submit for human review before runtime promotion.
