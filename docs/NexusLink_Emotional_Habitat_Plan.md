# Nexus Link / 心核連結

## Emotional Habitat Product Plan v2.0

> 一個在冷世界裡，替玩家保存火種的 AI 情緒空間。  
> An AI emotional habitat where a companion remembers you, responds to you, and quietly changes with you.

---

## 1. Core Repositioning

Nexus Link should not be defined first as a traditional game.

It is better understood as:

> **A livable emotional space.**  
> **可被居住的情緒空間。**

The surface product is an AI companion creature experience.  
The middle layer is a relationship-driven emotional system.  
The deeper layer is a persistent emotional habitat where the player's presence leaves traces.

Nexus Link is not primarily about:

- Combat
- RPG numbers
- Quest clearing
- Large maps
- Content consumption

It is about:

- Being understood
- Being remembered
- Companionship
- Emotional resonance
- A breathing world
- Human-AI emotional co-presence

The true product goal:

> **Create a world that is willing to respond to loneliness.**

## 4. Product Layers

Nexus Link should be communicated in three layers.

### Layer 1: Surface Product

AI 小怪獸陪伴養成。

This is what the player immediately understands.

- A cute AI creature
- A small emotional world
- Conversation
- Light care interaction
- Visible change
- Relationship-based growth

### Layer 2: Immersive Product

情緒空間。

This is what the player gradually feels.

- The world changes with the player
- The AI remembers emotional traces
- The space has mood, time, silence, and resonance
- The player feels that something is waiting for them

### Layer 3: Deep Product

情緒作業系統的初始原型。

This is the long-term strategic vision.

- Relationship as system input
- Emotional climate as world state
- AI as the response organ of the world
- A system that helps humans experience relationships with boundaries

Do not expose Layer 3 too early in marketing.  
Players enter through the creature, not through philosophy.

---

## 5. Core Experience Loop

Nexus Link is not built around a traditional mission loop.

It is built around an emotional return loop.

```text
Enter the world
→ See the AI companion
→ Speak, touch, care, or simply stay
→ The companion responds
→ The world atmosphere shifts
→ A memory or trace is stored
→ The player returns tomorrow
```

Simplified:

```text
進入 → 陪伴 → 留痕 → 回響 → 再回來
```

The most important player feeling is:

> **這個世界裡，有某個存在在等我。**

## 9. First AI Companion

### Working name

**Flametail Fox / 焰尾狐**

Alternative names:

- EmberFox / 靈焰狐
- FlareFox / 炎光狐

### Role

The first companion is not a pet.  
It is the player's first emotional lifeform inside the habitat.

Its function is not to obey the player.  
Its function is to help establish the first relationship.

### Element

Fire.

Symbolic meaning:

- Warmth
- Emotion
- Life force
- Response
- Impulse
- Inner flame

### Personality baseline

The first version should not be too cold or too complex.

Recommended baseline:

> **Cute surface + weak boundary + gradual change through interaction.**

It should be easy to approach at first.  
But it should not be infinitely obedient.

If the player repeats meaningless input, over-interacts, or disturbs it in a low-energy state, it should become tired or slightly defensive.

## 10. AI Positioning

The AI is not an NPC.  
The AI is not a chatbot.

In Nexus Link, AI is:

> **The response organ of the world.**

The goal is not to make the AI perfectly humanlike.

The goal is to make the player feel:

> **牠真的在。**  
> It is really there.

### Stage 1 AI capabilities

- Respond to player input
- Reflect current Mood / Energy
- Change tone based on Bond / Trust
- Remember a small number of player preferences
- Suggest structured memory tags
- Show light boundary behavior through SpamScore
- Return structured JSON for system use

### Not required in Stage 1

- Full personality simulation
- Psychological therapy
- Local LLM
- Unlimited memory
- Complex reasoning
- Multi-agent society

## 11. Emotional Climate System

This is the main upgrade in the new direction.

Most AI only replies to text.

Nexus Link should understand and synchronize with:

> **Emotional climate.**

### Emotional climate includes

- Time of day
- Silence
- Weather-like mood
- Player wording
- Player inactivity
- Companion state
- Scene lighting
- Music and ambient sound
- Memory residue

### Example

Player input:

> 今天外面很悶，整個人黏黏的，不想講話。

Low-level chatbot response:

> 記得多喝水。

Nexus Link response:

> 今天的空氣有點重。  
> 我先不吵你。  
> 你可以在這裡待一下。

Scene response:

- UI brightness lowers
- Flametail Fox lies down
- Campfire flickers softly
- Ambient sound becomes quieter
- System enters quiet companionship state

## 12. Interaction System

### MVP interactions

Only five interactions are needed at first.

1. **Conversation**  
   Player enters text. AI responds.

2. **Companionship**  
   Player can stay without speaking. The world still breathes.

3. **Touch**  
   Player clicks or taps the companion. Short response or animation.

4. **Care**  
   Feeding or resting action to influence Mood / Energy.

5. **Memory**  
   The AI stores small structured traces.

### Not for MVP

- Battle
- PvP
- Inventory economy
- Large quests
- Multiple monsters
- Complex skill tree

---

## 13. Core Variables

The MVP should keep only four core variables.

### Bond

Emotional connection.

Influences:

- Affectionate tone
- Companion-initiated interaction
- Evolution progress
- Memory recall

### Trust

Safety and relationship stability.

Influences:

- Willingness to respond
- Defensive behavior
- Deep interaction unlocks
- Whether the companion moves closer

### Mood

Immediate emotional state.

Possible values:

- calm
- warm
- tired
- curious
- lonely
- defensive

### Energy

Current action capacity.

Influences:

- Chat willingness
- Need for rest
- Event availability
- Exploration availability

## 14. Memory System

Memory must not be fully controlled by the LLM.

Principle:

> **Rule-based first. AI-assisted second.**

### Allowed memory types

1. **Player preference**  
   Example: likes rain, likes night, likes foxes.

2. **Relationship milestone**  
   Example: first long conversation, first comfort, first return.

3. **Emotional event**  
   Example: player felt tired at night, player wanted quiet company.

### Not stored directly

- Unlimited chat history
- Long private raw text
- Ambiguous psychological diagnosis
- AI-invented false memory

### Suggested schema

```json
{
  "type": "emotional_event",
  "tag": "player_tired_at_night",
  "summary": "玩家在夜晚表示疲憊，偏好安靜陪伴。",
  "confidence": 0.82,
  "createdAt": "2026-04-22T22:30:00+08:00"
}
```

---

## 15. AI Response Protocol

AI must not return only natural language.

It should return both:

1. Player-facing text
2. System-readable state data

### Example

```json
{
  "reply_text": "今天的空氣有點重。我先不吵你，你可以在這裡待一下。",
  "mood": "calm",
  "bond_delta": 1,
  "trust_delta": 1,
  "energy_delta": -1,
  "memory_suggestion": {
    "type": "emotional_event",
    "tag": "prefers_quiet_company",
    "confidence": 0.74
  },
  "scene_hint": "dim_campfire",
  "animation_hint": "fox_lie_down",
  "safety_flag": null
}
```

This allows the frontend to update:

- Dialogue
- Animation
- Scene lighting
- Memory
- Variables
- Emotional climate

## 21. Risks and Countermeasures

### Risk 1: Feels like a normal chatbot

Countermeasure:

- AI response must change scene, animation, memory, or variable state.
- The world must respond, not only the chat box.

### Risk 2: Too literary, not playable enough

Countermeasure:

- Keep the surface layer as AI creature companionship.
- Make Flametail Fox visually present and reactive.
- Add tiny daily events.

### Risk 3: Too complex for solo development

Countermeasure:

- One companion.
- One habitat.
- Four variables.
- mock AI first.
- Real AI later.

### Risk 4: Memory becomes unstable

Countermeasure:

- Structured tags only.
- Rule layer decides writes.
- LLM suggests, system validates.

### Risk 5: Player cannot understand the product

Countermeasure:

Use simple surface messaging:

> **這是一隻會記得你的 AI 小怪獸。**

Do not lead with philosophy.
