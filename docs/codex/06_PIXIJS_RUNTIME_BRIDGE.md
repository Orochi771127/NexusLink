# 06 — PixiJS Runtime Bridge

This document defines how Nexus Link's Web/PixiJS runtime should consume layered assets generated by an external scene pipeline such as Unity/UModeler.

## Runtime Position

The Web/PixiJS runtime remains the active product path.

Unity or other authoring tools may generate assets, but PixiJS remains responsible for:

- loading scene manifests
- loading PNG layers
- positioning layers
- applying parallax
- applying lightweight ambience effects
- keeping the companion grounded and readable
- preserving mobile performance

## Input Contract

A layered scene should be delivered as a folder containing:

```text
<scene-id>/
  manifest.json
  Background.png
  Midground.png
  Foreground.png
  Overlay.png
```

`Overlay.png` may be omitted only if the manifest marks it optional or does not list it.

## Manifest Contract

Minimum supported manifest shape:

```json
{
  "sceneId": "moonlake-camp-habitat",
  "version": 1,
  "size": {
    "width": 1920,
    "height": 1080
  },
  "layers": [
    {
      "id": "background",
      "src": "Background.png",
      "parallax": 0.05,
      "zIndex": 0
    },
    {
      "id": "midground",
      "src": "Midground.png",
      "parallax": 0.12,
      "zIndex": 10
    },
    {
      "id": "foreground",
      "src": "Foreground.png",
      "parallax": 0.2,
      "zIndex": 20
    },
    {
      "id": "overlay",
      "src": "Overlay.png",
      "parallax": 0.16,
      "zIndex": 30,
      "alpha": 1,
      "optional": true
    }
  ]
}
```

## Loader Responsibilities

A future PixiJS scene loader should:

1. fetch `manifest.json`
2. validate `sceneId`, `version`, `size`, and `layers`
3. resolve layer paths relative to the manifest folder
4. load each texture through the existing asset-loading strategy
5. create a deterministic display container per layer
6. sort by `zIndex`
7. scale layers to the game viewport consistently
8. apply subtle parallax based on camera/mouse/device-safe offsets
9. avoid interfering with companion anchor positioning
10. fail gracefully if optional overlay is missing

## Performance Rules

Mobile-first constraints:

- do not load unnecessary 4K textures on small devices
- avoid too many simultaneous full-screen alpha layers
- avoid expensive blend modes by default
- avoid heavy particle systems unless already performance-tested
- prefer subtle motion over high-frequency effects
- cache textures when switching scenes only if memory budget allows it

## Visual Behavior Targets

Layering should support:

- light parallax
- scene breathing
- water shimmer
- crystal flicker
- fog or glow overlay
- depth separation between companion and environment

The environment must not reduce UI readability or make companion silhouettes unclear.

## Companion Grounding Rule

The foreground/platform layer must support stable bottom-center companion anchoring.

A future loader should not shift companion position based on full scene image bounds unless explicitly designed. Companion anchoring is governed by the companion runtime policy and sprite metadata, not arbitrary background image placement.

## Suggested Runtime Structure

If implemented, prefer small modules such as:

```text
src/pixi/
  layeredSceneLoader.js
  sceneLayerManifest.js
  habitatParallaxController.js
```

However, adding files under `src/pixi/` may be high-risk if it touches existing runtime bootstrap. Follow `AGENTS.md` groundwork protocol when touching high-risk files.

## Non-Goals

This bridge must not:

- introduce React, Vue, Svelte, TypeScript, npm, or a build step
- replace existing PixiJS bootstrapping without approval
- change save-state shape unless scene unlock/progression is part of the approved task
- introduce Unity runtime dependencies into the Web build
- convert Nexus Link into a generic RPG map viewer

## Acceptance Criteria For Future Loader Implementation

A future implementation should pass these checks:

- a manifest with four layers loads without console errors
- missing required layer produces a readable error
- missing optional overlay does not break scene loading
- layer order is deterministic
- parallax can be disabled for accessibility/performance
- companion remains visually grounded
- UI remains readable above scene content
- no new dependency or build step is introduced
